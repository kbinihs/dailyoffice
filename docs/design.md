# Design — 매일, 함께

> 관련 문서: [[prd]] · [[implementation_plan]]
> 이 문서는 "무엇을 어떻게 보여 주고, 데이터가 어떻게 흐르는가"를 다룬다. 기도문 본문 자체는 콘텐츠 작업에서 만든다.

## 1. 정보 구조

```
앱 (처음 열 때 첫 화면 모션)
├─ 홈
│   ├─ 오늘의 인용 (매튜 헨리, 날마다 바뀜)
│   ├─ 오늘의 기도 (아침 · 낮 · 밤, 해 뜸·한낮의 해·달 아이콘)
│   └─ 오늘의 말씀 (오늘 범위 · 진도)
├─ 기도 (모은 두 손 아이콘)
│   ├─ 아침  (짧은 형식)
│   ├─ 낮    (짧은 형식)
│   └─ 밤    (본 예식)
├─ 말씀
│   ├─ 오늘
│   ├─ 밀린 날
│   └─ 진도
└─ 설정 (상단 바의 설정 단추)
    ├─ 글자 크기 · 화면 밝기
    ├─ 기록 내보내기 · 가져오기
    └─ 정보 (출처 · 저작권 고지)
```

하단 탭 세 개: 홈 / 기도 / 말씀(2026-11-02 디자인 적용으로 바뀜). 앱을 열면 첫 화면 모션 뒤 홈. 기도 탭은 현재 시각으로 시간대를 고른다(05–11 아침, 11–17 낮, 그 외 밤), 상단에서 수동 전환. 홈의 시간대 타일을 누르면 그 시간대 기도로 간다. 설정은 하단 탭이 아니라 각 화면 상단 바의 설정 단추로 연다.

## 2. 두 모드 — 혼자가 원형이다

| | 혼자 (기본값) | 함께 |
|---|---|---|
| 역할 라벨 | 표시하지 않음. 인도자·나머지·다 함께가 한 흐름으로 이어짐 | 표시 |
| 인도자 | 없음 | 이름 목록에서 선택. 선택한 사람의 줄을 강조 |
| 축복(밤) | 2인칭 본문을 "받는 말씀"으로 읽음 | 서로를 향해 2인칭, 또는 1인칭 복수 중 선택 |
| 체크 | 시간대별 1회 | 같음(기기 단위) |

설계 원칙: 함께 모드는 혼자 모드 위에 라벨과 강조를 **덧입히는** 것이다. 데이터는 하나, 렌더링만 다르다. 혼자 모드가 결핍으로 읽히는 문구(예: "가족과 함께하세요")를 쓰지 않는다.

이름 저장: 기기 로컬. 호칭·관계·나이를 묻지 않는다. 이름 대신 별명도 된다. 이름은 기도 화면의 인도자 칩에서만 더하고 뺀다(설정 화면에는 두지 않는다, 2026-11-02).

### 3.4 절기

| 절기 | 기간 | 여는 말씀 | 절기 기도 |
|---|---|---|---|
| 대림절 | 대림절 첫 주일 ~ 12/24 | 대림 | 대림 1~4주 |
| 성탄절 | 12/25 ~ 1/5 | 성탄 | 성탄일, 성탄 후 1·2주 |
| 사순절 | 재의 수요일 ~ 종려주일 전날 | 사순 | 재의 수요일, 사순 1~5주 |
| 고난주간 | 종려주일 ~ 성토요일 | 고난주간 | 종려주일(일~수), 성목·성금·성토요일은 그날 기도 |
| 부활절 | 부활주일 ~ 성령강림주일 | 부활 / 승천(승천일~) / 성령강림(당일) | 부활주일, 부활 2~7주, 승천일 |

- 기도는 가장 최근 주일(또는 축일)의 기도를 그 주 내내 쓴다. 아침·밤 예식에서 요일 기도 **앞에** 더한다.
- 절기 여는 말씀이 요일 여는 말씀을 대신한다.
- 그 밖의 기간(주현절, 성령강림 후)은 평상시 예식이다.
- 날짜 규칙과 2026~2030년 검산표는 `content/seasons.json`.
- 절기 기도 본문은 BCP 2019 Collects of the Christian Year(pp.597-613).

## 4. 날짜 → 본문 함수

모든 가변 본문은 **기기 상태가 아니라 날짜**로 정한다. 함수 하나로 모은다.

```
resolve(date):                          // date는 04:00 경계를 적용한 '기도 날짜'
  weekday    = date.getDay()            // 0=일 … 6=토
  psalterDay = psalterIndex(date)       // 1~182
  missionIdx = daysSinceEpoch(date) % 3 // 연·월 경계에서 끊기지 않게 epoch 기준
  planDay    = planIndex(date)          // 1~276, 주일·통독 기간 밖이면 null
  season     = seasonOf(date)           // advent | christmas | lent | holyweek | easter | null
  openingKey = openingSeasonOf(date)    // 부활절 안에서 easter | ascension | pentecost
  collectId  = collectOf(date)          // adv1 … pentecost, 절기 밖이면 null
  return { weekday, psalterDay, missionIdx, planDay, season, openingKey, collectId }

psalterIndex(date):
  doy = dayOfYear(date)
  return doy <= 364 ? ((doy - 1) % 182) + 1 : 182 - (daysInYear - doy)

planIndex(date):                        // 설정은 content/plan-config.json
  if date < startDate or weekday in restWeekdays: return null
  n = startDate부터 date까지(양 끝 포함) 쉬는 요일을 뺀 날 수
  return n <= totalDays ? n : null
```

- 시편: 1월 1일과 7월 2일(윤년 7월 1일)에 1편부터. 364일을 넘는 날(12월 31일, 윤년은 30·31일)은 마지막 분량을 한 번 더 읽는다.
- 통독: 일요일을 뺀 주 6일. 주일에는 새 범위가 없다.
- 절기: 부활절(그레고리력 계산식)과 대림절 첫 주일에서 모든 경계를 계산한다. 성탄절은 해를 넘기므로 1월 1~5일은 전해 성탄절로 본다. 규칙은 `content/seasons.json`.

- `daysSinceEpoch`는 로컬 자정 기준. 시간대(Asia/Seoul) 고정.
- 시간대 전환(아침→밤)과 날짜 전환은 분리한다. 새벽 1시에 연 '밤' 예식은 전날 밤으로 본다(04:00을 하루 경계로 둔다).

## 5. 데이터 모델

모두 정적 JSON. 빌드 시 번들에 포함되거나 책 단위로 지연 로드.

### 5.1 기도 요소 `content/elements.json` (v0.1 뼈대 작성: 24요소, 변형 103개, 번역 대상 48편)

```json
{
  "id": "evening.collect.weekday",
  "title": "요일 기도",
  "role": "leader",            // leader | people | together | mutual
  "soloOmit": false,
  "variants": [
    { "when": { "weekday": 0 }, "text": "..." },
    { "when": { "weekday": 1 }, "text": "..." }
  ]
}
```

- `when`은 `weekday` / `psalterDay` / `cycle3` / `default` 중 하나. `default`만 있으면 고정 본문.
- `mutual`은 축복 전용. 혼자 모드에서는 `people` 없이 그대로 표시.
- 교독(시편)은 요소가 아니라 `psalter` 타입으로 따로 처리한다(절 데이터가 성경 본문에서 온다).

{
  "evening": ["evening.opening", "common.confession", "psalter.evening",
              "common.lordsPrayer", "evening.collect.weekday",

### 5.3 시편 182일 주기 `content/psalter-cycle.json` (작성 완료)

```json
{ "meta": { "cycleLength": 182, "dateRule": "…" },
  "days": [ { "day": 18, "label": "시편 18:1-19", "refs": [{ "ps": 18, "from": 1, "to": 19 }], "verses": 19 }, … ] }
```

- 1년 2독. 하루 한 편을 원칙으로 하고, 긴 시편 15편(18, 35, 37, 68, 69, 78, 89, 102, 104, 105, 106, 107, 109, 118, 119편)만 단락에서 나눈다. 150편 + 32일 = 182일.
- 119편은 두 연(16절)씩 11일. 22편과 73편은 탄식에서 찬양·깨달음으로 넘어가는 전환이 한 편 안에 있어 나누지 않는다.
- 개역한글 절 구분 기준 2,461절이 한 번씩 들어갔는지 검사했다. 검토용 표는 `content/psalter-cycle.csv`(2026년 날짜 포함).

### 5.4 성경 본문 `bible/krv/<book>.json`

```json
{ "book": "Ps", "chapters": { "1": { "1": "복 있는 사람은 …", "2": "…" } } }
```

- 개역한글(1961). 원천 후보는 GitHub `bluesaurel/Korean-Bible-1961-KRV`(66권 1,189장 31,102절, 1961년 맞춤법 보존). `jesusdasom/RHB`(CC0)는 시편 72:19-20이 한 절로 합쳐져 있어 대조용으로만 쓴다. bluesaurel 데이터는 라이선스 표기가 없어 이용 조건 확인 필요.
- 책 단위 파일. 시편·통독 범위에 해당하는 책만 그때 불러온다.

### 5.5 통독표 `content/plan.csv` + `content/plan-config.json` → 빌드 시 `plan.json`

```
일차,범위,핵심장,refs,key_ref
1,창세기 1~5,3장,Gen 1-5,Gen 3
24,레위기 26~민 3,26장,Lev 26-27; Num 1-3,Lev 26
```

```json
{ "planId": "2026", "startDate": null, "restWeekdays": [0], "totalDays": 276 }
```

- 통독표는 날짜가 아니라 **일차**로 되어 있다(2026 그리스도 중심 성경읽기표, 276일). 일요일을 뺀 주 6일로 날짜에 대응시킨다(4절 `planIndex`).
- `범위`·`핵심장`은 PDF 표기 그대로, `refs`·`key_ref`는 기계가 읽는 범위(장 단위, 복수 범위는 `;`로). 1,189장이 순서대로 빠짐없이 들어 있는지 검사했다.
- `startDate`가 `null`이면 그해 1월 1일에 시작한다. 같은 통독표를 다시 쓰면 해가 바뀌어도 고칠 것이 없고, 통독표가 바뀔 때만 CSV를 교체한다. 빌드가 JSON으로 바꾼다.
- 통독표의 시편 범위(109~132일차)는 밤 예식 시편과 연결하지 않는다. 밤 예식은 늘 5.3의 182일 주기를 쓴다.

### 5.6 로컬 상태 (IndexedDB)

```
checks:   { date: "2026-11-02", morning: true, midday: false, evening: true }   // 기도는 날짜 기준
reading:  { "2026": { "262": true } }                                         // 통독은 연도·일차 기준. 열쇠는 통독을 시작한 해
people:   ["효은", "아빠"]        // 함께 모드 이름 목록
settings: { fontScale: 1.2, theme: "auto", mode: "solo", lastLeader: "효은" }
```

내보내기는 위 네 개를 JSON 하나로. 가져오기는 병합(같은 날짜·일차는 OR).

기기에 쓸 때는 통째로 덮지 않고 "기기의 값을 읽고 → 바꿀 것만 바꿔 → 쓰기"로 한다(같은 기기에서 탭·창을 둘 열어도 서로의 체크를 지우지 않게). 기록을 다 불러오기 전에는 화면을 그리지 않고, 처음 불러오기에 실패하면 그 실행 동안은 기기에 쓰지 않는다.

### 5.7 절기 `content/seasons.json` (작성 완료)

- 절기 5개의 시작·끝, 절기 기도 26편의 적용 구간, 여는 말씀 하위 구간(부활·승천·성령강림)을 기준일(부활절, 대림절 첫 주일)로부터의 거리로 적는다.
- 2026~2030년 기준일 검산표를 함께 둔다(2026년 부활절 4월 5일, 대림절 첫 주일 11월 29일).

## 6. 화면

### 6.1 기도 화면
- 상단: 시간대 토글(아침·낮·밤), 모드 토글(혼자·함께), 함께 모드일 때 인도자 칩.
- 본문: 요소를 세로로 이어 보여 준다. 스크롤 하나로 끝까지. 페이지 넘김 없음(함께 읽을 때 "다음" 누르는 사람이 생기면 흐름이 끊긴다).
- 역할 표시(함께 모드): 교독·주고받음은 **인도자 줄 굵게, 나머지 보통 글꼴**로 구분하고 줄마다 라벨을 달지 않는다. 예식 맨 위 안내문에 "굵은 글씨는 인도자(이름)가 읽습니다" 한 줄. 인도자 혼자 읽는 기도는 제목 옆에 작은 라벨. '다 함께'는 배경 강조.
- 하단 고정: "기도를 마쳤습니다" 버튼 → 체크. 다시 누르면 해제.
- 기도 중 화면 꺼짐 방지(Wake Lock, 가능한 기기만).

### 6.2 읽기 화면
- 상단 한 줄: "오늘 {label}을 읽습니다." 교회 이름은 화면에 넣지 않는다([Bin] 2026-11-02).
- 본문: 범위의 장을 이어서. 장 제목 사이 여백.
- 하단 고정: "읽었습니다" 체크.
- 밀린 날: 상단의 "오늘 · 밀린 날 N · 진도" 중 "밀린 날"을 누르면 목록 화면으로 간다(접기·펼치기 대신 화면을 나눈다). 일차별로 열고 체크하면 "다음 밀린 날"로 이어진다. 밀린 날은 처음 체크한 일차부터 어제까지 세어, 연중에 시작한 사람에게 앞의 날을 모두 들이밀지 않는다. 경고색을 쓰지 않는다.
- 진도: 달력 모양 한 달 뷰, 읽은 날 점 표시. 숫자 퍼센트 하나. 그 이상의 통계는 두지 않는다.
- 주일: "주일 — 통독 쉼". 밀린 날 목록만 보인다.
- 통독 기간이 끝난 뒤(마지막 일차 이후): "올해 통독표를 마쳤습니다"와 밀린 날 목록. 새 통독표가 올라오면 바뀐다.

### 6.3 설정
- 글자 크기 슬라이더(기본 18px, 14–28), 테마.
- 기록: 내보내기(JSON 다운로드), 가져오기(파일 선택), 전체 삭제(확인 2단계).
- 정보: 기도문 출처(BCP 2019 번역), 성경 표기("성경전서 개역한글판 © 대한성서공회", 주기도문 새주기도문), 코드 저장소 링크. 근거는 [[rights]].

## 10. 기술 선택

| 항목 | 선택 | 이유 · 트레이드오프 |
|---|---|---|
| 빌드 | Vite + TypeScript | 가볍고 PWA 플러그인 성숙. 프레임워크 없이 시작(DOM 직접). 화면이 셋이라 상태 관리 부담이 작다. 복잡해지면 Preact로 옮긴다 |
| PWA | vite-plugin-pwa(Workbox) | 오프라인 캐시, 설치 프롬프트 |
| 저장 | IndexedDB(idb-keyval) | localStorage 5MB 한계 회피. 내보내기 쉬움 |
| 호스팅 | GitHub Pages + Actions(공개 저장소 `kbinihs/dailyoffice`) | 비용 0. main에 푸시하면 테스트 → 빌드 → 배포. 2026-11-02 [Bin] 결정 |
| 성경 데이터 | 정적 JSON, 책 단위 | 서버 없음. 첫 로드를 작게 |
| 분석 | 없음 | 개인정보 수집 0 유지 |
| UI 컴포넌트 | `@material/web`(Google Material 3 웹 컴포넌트, Lit 기반) | 2026-11-02 추가([Bin] 결정). 프레임워크 없이 DOM에 그대로 쓰는 웹 컴포넌트라 "DOM 직접" 원칙과 맞는다. 쓰는 것만 하나씩 가져온다(물결·초점·아이콘·단추·FAB·대화창·슬라이더·탭·칩·목록·입력칸). 실험(labs) 컴포넌트는 쓰지 않는다. 트레이드오프: 번들이 커지고(lit 포함), 컴포넌트 안쪽(그림자 DOM)은 `--md-*` 변수로만 꾸민다 |
| 글꼴·아이콘 | Google Fonts(Noto Sans KR, 나눔고딕, Material Symbols Rounded 선 아이콘 한 벌) | 서비스 워커가 처음 쓸 때 담아 두어 오프라인에서도 같은 모양. 아이콘은 쓰는 이름만 받는다(`index.html`) |

의존성은 `vite`, `vite-plugin-pwa`, `idb-keyval`, `typescript`, `@material/web` 다섯 개를 넘기지 않는다(`@material/web`이 끌어오는 `lit` 등은 그 일부로 본다).

## 11. 보류한 설계

- 주현절·성인 축일: `seasons.json`에 절기를 더하는 방식으로 넓힐 수 있다. 2차.
- 다교회: `config/<church>.json`으로 분리 가능하게 경로만 잡아 둔다.
- 알림: 웹 푸시는 서버가 필요해 "서버 없음" 원칙과 충돌한다. 넣는다면 로컬 알림(지원 제한) 또는 원칙 수정을 먼저 결정한다.
- **백엔드(2026-11-02 검토, [Bin] 결정: 정적 구조 유지)**: 세 안을 견주었다. A 지금 구조(정적 PWA, 기록은 기기에만) / B A + 알림만 작은 서버리스(이름·기록은 두지 않고 알림 구독 주소만) / C 무료 백엔드(로그인·동기화·소그룹 나눔). C는 "누가 언제 기도했는가"가 신앙에 관한 정보라 개인정보보호법 23조 민감정보 처리(별도 동의·처리방침·안전조치)가 교회 몫이 되고, 서로의 기록이 보이면 기도가 점검·비교가 되기 쉬워(PRD 9절 "결핍감 없음", 화면 원칙 9) 택하지 않았다. 공동체로 넓히는 길은 서버 없이: 같은 날 같은 본문(날짜 계산), 교회 소식·기도 제목은 운영자가 고치는 정적 JSON, 나눔은 이미 있는 카카오톡 단톡방으로 공유, 교회별 설정 파일. 파일럿 설문에서 알림을 원하면 B부터 다시 본다.
