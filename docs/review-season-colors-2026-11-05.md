# 검토 — 절기별 색 (2026-11-05)

> 2026-11-05 [Bin]이 B안으로 결정, 같은 날 구현함(평상시 초록, 대림 파랑, 성금요일·성토요일 검정, 장미색은 뺌). 아래는 결정 전의 검토 그대로.

[Bin]의 물음: 앱의 색을 전례색에 맞춰 절기마다 바꿀 수 있을까. 색만 바뀌어도 "내가 이런 시기를 살고 있구나"를 알게 하고 싶다. 구현보다 먼저, 어떻게 할 수 있는지와 유익·손해를 본다.

## 1. 결론부터
- **할 수 있다. 작게 하면 유익이 손해보다 크다.**
- 권하는 안은 **"강조색만 절기색으로, 면과 글자색은 그대로"**(아래 B안) + 날짜 줄에 절기 이름 + 설정에 끄는 토글(기본 켬).
- 표의 여덟 색을 그대로 쓸 수는 없다. 금·장미는 글자색으로 쓰면 명암비가 모자라고, 흰색은 밝은 화면에서 안 보이며 다크 모드에서는 성립하지 않는다. 성탄·부활은 "크림색 면 + 금 강조"로 풀고, 장미색은 빼거나 면 색으로만 쓴다.
- 가장 큰 결정은 **평상시 색**이다. 전례색을 따르면 1년의 절반 이상이 초록이 되고, 교회 보라(#403966)는 아이콘·첫 화면에만 남는다. 평상시를 보라로 두면 사순절(보라)이 평소와 구별되지 않는다.

## 2. 지금 구조에서는 이렇게 된다
- 날짜 → 절기는 이미 있다. `resolve(date)`가 `season`(advent / christmas / lent / holyweek / easter / null)과 `openingKey`(easter / ascension / pentecost), `collectId`(adv3, lent4, goodfri, holysat, pentecost …)를 돌려준다. 색은 이 값에서 **날짜로 계산**된다(규칙 2). 기기 상태가 아니다. `?date=`로 미리 볼 수 있다.
- 색은 `src/style.css`의 `:root`에 M3 색 역할 토큰 35개(밝음) + `prefers-color-scheme: dark` 블록으로 있고, `@material/web` 컴포넌트와 직접 만든 탭·단추가 모두 이 변수를 읽는다. 상태 표시줄 색(`theme-color`)은 `src/display.ts`가 `--md-sys-color-surface`를 따라가게 해 두었다.
- 그러니 `<html data-season="lent">`처럼 속성 하나를 붙이고, CSS에서 그 속성 아래 토큰 몇 개만 덮어쓰면 앱 전체가 따라간다. 의존성 추가 없음, 서버 없음, 오프라인 그대로, 서비스 워커 캐시 변화 없음(CSS 한 파일).

구현 단계(B안 기준, 반나절~하루):
1. `content/seasons.json`에 `color` 필드(또는 `content/liturgical-colors.json`)로 절기·구간 → 색 이름(violet / blue / white / gold / green / red / rose / black)을 **데이터로** 적는다.
2. `src/core/resolve.ts`에 `liturgicalColor(r)`(순수 함수)을 더한다. 우선순위: 하루짜리(성금요일·성령강림일) > 하위 구간(승천) > 절기 > 평상시.
3. `src/main.ts`의 화면 그리기에서 `document.documentElement.dataset.season = …`(04시 경계·`?date=` 포함).
4. `src/style.css`에 `:root[data-season='violet'] { --md-sys-color-primary; --md-sys-color-primary-container; --md-sys-color-on-primary-container; (--md-sys-color-tertiary …) }`를 색마다, 밝음·어두움 두 벌.
5. 날짜 줄("2027년 2월 14일 일요일 · 아침 · 4~6분")에 절기 이름을 넣는다: "… · 사순절 첫째 주". 색이 왜 바뀌었는지 한눈에 알게.
6. 설정에 "절기 색" 토글(기본 켬). 이미 설정은 `idb-keyval`에 저장한다.
7. 테스트: 2026~2030 검산표 날짜별 색 표(`tests/resolve.test.ts`), 그리고 의존성 없는 명암비 검사 스크립트(`scripts/check-contrast.mjs`)로 글자색 쌍이 AA(4.5:1)를 넘는지 확인.
8. `docs/design.md` 8절에 적는다.

## 6. 유익
- **절기의 리듬이 화면에서 느껴진다.** 열자마자 "사순절이구나". [Bin]이 바라는 바로 그것. 절기 기도·알렐루야와 같은 원리(날짜로 계산)라 설계와도 맞는다.
- **싸다.** 데이터 몇 줄 + CSS 변수 + 순수 함수 하나. 의존성 0, 서버 0, 오프라인 그대로(규칙 1·2·7).
- **검산할 수 있다.** 절기 검산표가 이미 5년치 있다.
- 교회로 넓힐 때 전례력을 가르치는 효과. 주보·예배 색과 맞으면 집과 교회가 이어진다.

## 7. 손해·위험
- **명암비.** 금·장미는 그 색 그대로 글자에 못 쓴다. 톤을 바꾸면 "그 색"이 아니게 된다. → 면 색으로만 쓰고 글자는 어두운 톤.
- **다크 모드.** 어두운 방의 밤기도가 기본 설계라 다크 품질이 먼저다. 색 8개 × 2벌을 손으로 잡고 검사해야 한다. 흰색은 다크에서 성립하지 않는다.
- **빨강 = 경고색.** 규칙 9(기도 화면에 경고색 없음)와 부딪힌다. 체크·단추가 빨개지면 '오류' 느낌. → 성령강림일 하루, 면 색 위주.
- **검정의 날.** 성금요일에 화면이 온통 회색이면 "고장났나" 할 수 있다. → 절기 이름 표시가 필요하다(5단계).
- **정체성.** 1년 대부분이 초록이 되면 "보라 앱"이 아니게 된다. → 아이콘·첫 화면(스플래시)·이름은 보라로 둔다. 스플래시에서 화면으로 넘어갈 때 색이 바뀌는 것은 자연스럽다(스플래시는 브랜드, 화면은 오늘).
- **당혹.** 어느 날 열었더니 색이 다르다. → 날짜 줄에 절기 이름, 설정에 끄는 토글.
- **전례 세부 논쟁.** 대림 보라/파랑, 고난주간, 성토요일, 장미색 — 한 가지로 정하고 `seasons.json`에 적는다. 교파에 따라 다르므로 "이 앱의 선택"으로 문서화.
- **유지.** 주현절·축일을 더할 때(design.md 2차) 색도 같이 정해야 한다. 데이터로 두면 한 줄이다.
- 성능·오프라인·설치에는 영향이 없다. 서비스 워커 캐시 목록도 그대로.

## 8. 권고
B안. 순서는 평상시 색 결정(초록 권장) → 대림 색 결정 → 색 데이터 → CSS 두 벌 → 절기 이름 표시 → 토글 → 검산·명암비 테스트 → design.md. 장미색은 1차에서 뺀다. 성탄·부활의 "흰색"은 크림 면 + 금 강조로 푼다.
